产品定义与实施口径

以下内容用于统一产品、业务与开发团队的理解。可见文案以页面中的英文为准；中文部分解释业务含义、计算方式和验收边界，不建议直接展示在正式 Dashboard 中。

模块定位 关键词定义 计算公式 状态规则 交互要求 数据接口 验收标准

1. 模块定位

Publishing Progress

回答“发布数量和预算执行是否跟上本月时间节奏、差距来自哪个产品或达人等级”。这是执行进度模块，核心是 MTD、Target、Remaining 与 Pace，不评价 GMV 等商业结果。

Publishing Results

回答“当前发布投入带来了什么业务结果、相对 Target 和上月同期表现如何”。这是结果模块，覆盖 Post、Budget、GMV、ROI、Views、CPM，不显示 Remaining 或 Pace。

3. 核心计算公式

指标 公式 显示规则
MTD Achievement MTD ÷ Target 四舍五入为整数百分比；Target 为 0 时显示 —。
Remaining Target − MTD 正数显示 Remaining；超目标时建议显示 Over Target / Over Budget，而不是负数。
Time Progress Elapsed Days ÷ Days in Month 参与 Pace 计算但不在主卡重复显示。本 Demo 为 17 ÷ 30 = 57%。
Pace MTD Achievement − Time Progress 显示带正负号的整数百分比，如 +16%、−3%。
vs Last Month (Current MTD − Last Month Same-period MTD) ÷ Last Month Same-period MTD 使用 ↑ / ↓ 与整数百分比；对比基数为 0 时显示 —。
ROI GMV ÷ Budget 保留两位小数；Budget 为 0 时显示 —。
CPM Budget ÷ Views × 1,000 保留两位小数；Views 为 0 时显示 —。

5. Scope、透视与交互要求

Scope

PIC 页面默认展示该 PIC 负责的全部产品与全部 Creator Tier，因此不提供额外产品或达人等级筛选器。Scope 标签仅说明当前范围。

Breakdown

两个模块均支持 Product、Creator Tier、Product × Creator Tier。切换透视只改变拆分方式，不改变顶部总数。

Publishing Results Toggle

默认只展示六项总览 KPI。点击 View Breakdown 展开明细，再次点击 Hide Breakdown 收起；切换透视时保持展开状态。

Aggregation

Product、Creator Tier 与交叉透视的所有子项必须严格汇总回顶部总数。ROI、CPM 必须用汇总后的原始指标重新计算，禁止对子项比率做平均。

6. 建议数据接口

后端建议返回原始可加总指标，由统一语义层计算 ROI、CPM、Achievement、Remaining、Pace 和 Last Month 对比，避免前后端口径漂移。以下为最小示意结构： 

{
  "asOfDate": "2026-06-17",
  "timezone": "Asia/Jakarta",
  "period": { "elapsedDays": 17, "daysInMonth": 30 },
  "scope": {
    "picId": "nadia",
    "productIds": ["serum-spray", "day-cream"],
    "creatorTiers": ["S", "A", "B"]
  },
  "summary": {
    "post":   { "mtd": 45, "target": 84, "lastMonthSamePeriod": 41 },
    "budget": { "mtd": 2900, "target": 7200, "lastMonthSamePeriod": 3900 },
    "gmv":    { "mtd": 33300, "target": 64000, "lastMonthSamePeriod": 30200 },
    "views":  { "mtd": 2190000, "target": 4200000, "lastMonthSamePeriod": 1980000 }
  },
  "breakdowns": {
    "byProduct": [],
    "byCreatorTier": [],
    "byProductCreatorTier": []
  }
}
ROI 与 CPM 不建议作为独立事实字段长期存储；应基于同一响应中的 GMV、Budget、Views 动态计算。若接口必须返回派生值，也需要同时返回原始值以便校验。

7. 验收标准

  • 所有可见模块文案为英文，且统一使用 Post、Budget、Target。
  • Progress 顶部总数与三种 Breakdown 汇总完全一致。
  • Results 顶部顺序固定为 Post、Budget、GMV、ROI、Views、CPM。
  • Results 每项 KPI 以 MTD 实际值为大数字，Target 作为下方灰色辅助信息。
  • Results 不显示 Remaining、Pace 或右上角状态颜色点。
  • vs Last Month 使用上月相同截止日，而非上月整月。
  • Target 为 0、对比基数为 0、Views 或 Budget 为 0 时不出现 Infinity / NaN。
  • ROI、CPM 使用汇总后原始值重算，不允许平均子项比率。
  • 桌面端无需横向滚动即可查看顶部 KPI；明细表在窄屏允许横向滚动。
上线前仍需业务确认四项口径：有效 Post 判定、Budget 入账时点、GMV / Views 归因窗口、每日数据截止时间。确认后应写入指标字典并由前后端共用。
