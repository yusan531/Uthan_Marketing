视频发布进度：三种重新设计方案

目标是让PIC在几秒内回答三个问题：已经发布多少、距离目标还差多少、当前速度是否跟得上时间。下方三种方案使用完全相同的数据和状态规则。

← Current Dashboard
目标差额 Use “Remaining”

39 Remaining 表示距月度目标的绝对数量，避免模糊的 Gap 39。

时间差额 Use “Pace”

−3% vs Time 直接对应完成率，保留节奏判断但不增加额外负反馈。

进度判断 Judge against time

月中不能只看54%完成率；应比较完成率与57%的时间进度。

Recommended direction

正式系统优先选择 A，并吸收 C 的行动句

A拥有最稳定的信息层级，适合作为PIC Dashboard默认主卡。当状态进入 Behind Plan 或 Critically Behind 时，再在卡片下方动态增加C方案的句子，例如 “3 more posts needed to return to today’s pace.”。这样正常状态保持简洁，异常状态才增加行动提示。

Recommended metric model

Completion Posted MTD ÷ Monthly Post Target 45 ÷ 84 = 54%
Remaining Post Target − Posted MTD 84 − 45 = 39 posts
Time Elapsed Current Day ÷ Days in Month 17 ÷ 30 = 57%
Pace vs Time Completion − Time Elapsed 54% − 57% = −3%

Design references

  • Material progress indicators: measurable progress should use a determinate indicator.
  • Tableau bullet graphs: a bar plus reference line supports primary-measure versus benchmark comparison.
  • WCAG 2.2 · Use of Color: status must include text or another cue, not color alone.
  • WAI-ARIA 1.2: progress components should expose current, minimum and maximum values programmatically.
  • GOV.UK status tags: status tags should describe state and should not look interactive.

阈值为产品设计建议，不是外部行业标准；正式上线前应根据历史月度波动、目标颗粒度和PIC可控动作校准。
